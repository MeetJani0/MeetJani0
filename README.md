```markdown
## 🧪 How I Think About AI Systems

Most real-world AI failures are not model failures — they are **system design failures**.

My usual workflow looks like this:

```

Messy Reality
↓
Representation Learning
↓
Retrieval (Vector / Evidence-based)
↓
Reasoning (LLMs / Deep Models)

```
## 🧙 Featured Project — Harry Potter Knowledge Assistant (RAG)

**FAISS · Gemini LLM · Streamlit · NLP**

An end-to-end **Retrieval-Augmented Generation system** built over all seven Harry Potter novels.

- Dense embeddings with per-book FAISS indexing

## 🧩 RAG System Architecture (How I Build It)

```

User Query
│
▼
Query Understanding
(Tokenization · Normalization)
│
▼
Embedding Model
(Dense Vector Representation)
│
▼
Vector Store (FAISS)
(Semantic Retrieval @ Top-K)
│
▼
Context Filtering
(Relevance · Deduplication · Length Control)
│
▼
Prompt Assembly
(Query + Evidence + Instructions)
│
▼
Large Language Model
(Grounded Generation)
│
▼
Answer + Supporting Evidence

```

**Design principle:**  
> Retrieval narrows the truth space.  
> The LLM reasons *inside* it.

This modular design allows retrieval, filtering, and generation to evolve independently.

## 🔭 Currently Exploring

I’m actively experimenting with next-generation AI system designs:

**🕸 Graph RAG**
- Knowledge graphs combined with vector retrieval  
- Entity-centric retrieval instead of chunk-centric search  
- Better multi-hop reasoning and long-context faithfulness  

**🤖 Agentic Systems**
- Tool-using LLM agents  
- Planner–Executor and ReAct-style architectures  
- Retrieval-aware agents that decide *when* to search, not just *how*

**🧪 Evaluation Beyond Accuracy**
- Faithfulness & grounding checks  
- Retrieval recall vs answer correctness  
- Failure-mode analysis for hallucinations  

This reflects what I’m learning *now*, not just what I’ve already completed.
```
